# NSP native audio backend

The product path of 2026-11-08 connects 48 kHz two-channel devices through `outputBackend: "wasapi"`, `outputLayout: "7.1.4"` and `lsac.enabled`. ROAR or LIRA rendering 7.1.4, LSAC downmix and equal loudness compensation before common DSP. Fixed sources support ROAR or LIRA, and unified inputs use ROAR OLR. See [Module Boundary](../../docs/runtime-details.md) and [WASAPI Example](../zig-scheduler/playback.wasapi.example.json).

2026-11-03: WASAPI has been connected to the Zig/FSA resident link, supporting JSON `wasapi.mode="shared"|"exclusive"`, default shared; `periodFrames` default 480, only used exclusively. Exclusively negotiates 48kHz stereo through the new native `nsp_wasapi_open_v2`, giving priority to Float32, otherwise 24/32/16-bit PCM; the same Rust Float32 pool is converted when finally writing the device buffer. The event exclusive writes the entire device buffer each time. If alignment fails, the client will be reactivated; if the application fails, an error will be clearly reported and the system will not silently change back to sharing. shared old ABI remains compatible. Build entry `Build-Wasapi.ps1` or CMake. Long-term asynchronous device clock drift compensation is still not implemented.

The native Realtek silent test supports 24 effective bits/32-bit containers, 480 frames 10ms and 240 frames 5ms, both 200 blocks/96000 frames are completely written out, only recycled and no overflow, shared regression passed. The current FSA selects exclusive/240 frames, and the DSP and master are maintained; this is a single device buffer cycle, not an end-to-end delay, and there is double buffering for event exclusives. Evidence `build/audio-backends/wasapi-exclusive-v1`, `build/lsac/wasapi-exclusive-001`.

WASAPI block-by-block diagnostics are built separately via `Build-Wasapi.ps1 -DiagnosticTrace -TargetDirectory build/audio-backends/wasapi-trace`. The device side management points are `src/wasapi_pool.cpp` and `src/wasapi_trace.h`, and the unified entrance and rendering side management points are `modules/croksor/src`. `Read-WasapiTrace.exe <Scheduling Process PID>` built from [Endpoint Diagnostic Reader](../../tools/endpoint-probe/Read-WasapiTrace.cpp) reads timestamps and frame numbers in the native shared ring while a session is running. Diagnostic DLLs, CSVs and reports are grouped under `build/`.

In the independent host experiment on 2026-11-02, `src/wasapi_pool.cpp` added 48kHz Float32 dual-channel WASAPI shared output. It receives the Rust output pool through the native C ABI, copies it once in the fixed-capacity FIFO and immediately returns the lease, and the device thread writes to the WASAPI buffer; it does not go through Python PCM callbacks and does not modify the default endpoint. Both FIFOs and Rust writers have bounded backpressure, and long-term asynchronous clock drift compensation has not yet been implemented. This round uses an independent verification host.

Historical real machine verification using `tools/lsac/Run-NotebookJoc.py` Using Movies and TV → MFT JOC decoding → Standard Windows spatial object submission → NSp audiodg capture → ROAR OLR 2.0 → Rust pool → Notebook WASAPI → EqAPO. `build/lsac/notebook-joc-live-008/report.json` records passed bounded pilot and revocation status; default decoy DTS:X HT endpoint remains unchanged, temporary MFT registration and controller are revoked on exit. `Test-WasapiPool.py` is the independent device consumption/rental pressure verification, and `Test-RoarStereo.py` is the real OLR Stereo verification without opening the device. The current FIFO has reached 64 480 frame blocks, and the results of this round cannot be claimed as low latency or that the audio and video synchronization acceptance has been completed.

2026-10-24: Both backends support the shared channel order of 5.1.2, 5.1.4, 7.1.2, 7.1.4, 7.1.6, 9.1.4, and 9.1.6. The only preset table is `contracts/output-layouts.json`. LIRA adds `nsp_spatial_create_layout`, the old create defaults to 7.1.4; 512 frames of inherent delay and room behavior remain independent. ROAR 6DoF slots are reserved only. See [Layout Contract](../../docs/archive/core/output-layout-presets-20261023.md).

Public DSP, recording and telemetry archiving are archived in the NSP hosting/bridging layer; ASIO only assumes device responsibility and is resident within the session. Side-recording is turned off by default, and when turned on, it will not write to disk in the output delivery or device callback thread. The device DLL must be matched with `libc++.dll`, `libunwind.dll` and loaded from the module directory. See [Side Recording Isolation](../../docs/archive/core/recording-isolation-20261024.md).

Only the modules extracted from Spatial ASIO and made available to NSP are kept: LIRA C ABI/Core, ASIO Device C ABI/Core, necessary public headers, coefficients/SDK, and isolation tests. The two sets of production DLLs are built separately without linking against the old full engine.

This does not include old `main.cpp`, capturers, plain PCM/WDM completion, full stream HT, Python capture management, WPF, fonts, installers or release projects. Compatible layout adaptation is for existing interface/test use only and does not go into the two production DLLs.

- Public host/pool block acceptance: `python tools/integration-tests/Test-OutputPool.py`.

DLL export names and existing configuration fields are preserved, and directory migration does not change sound, PCM protocols, or driver policies. For source and license, see [LICENSING.md](LICENSING.md); the complete downstream project is retained outside the workspace and is not used as a mainline build dependency. `source-manifest.json` hashed file by file when saving and extracting, subsequent modifications shall be subject to the version history.

This module has no .NET/WPF dependencies for production builds and runs. The C# client retained in the warehouse is only used for optional control testing and is not linked or loaded into this module, nor is it used as an implementation dependency of the new Web API host.
