# AES67 network audio output (branch prototype)

> Status (branch `feat/aes67-network-output`): a **standalone, tested** RTP/L24
> transmitter plus the integration design for NSP. It is **not** wired into the
> runtime yet; NSP's audio output is still ASIO-only. See
> `tools/aes67-output/INTEGRATION.md` and `BRANCH.md`.
>
> This page follows the project's direction bullet
> `README.md:48-50` ("Add native network-audio output alongside the current
> ASIO path") and the known gap that AoIP/Inferno is documented but not
> implemented.

## 1. Why AES67 fits this architecture

NSP's output stage already hands out **pool leases**: the Rust renderer owns
pre-allocated 480-frame blocks, the Zig common DSP processes them in place, and
a device owner submits borrowed pointers before returning them
(`tools/zig-scheduler/output_stream.zig:26-36,166-204`,
`docs/core/output-pool-processing-20261022.md`). AES67 needs exactly the same
shape: a paced, bounded sink that consumes interleaved 48 kHz PCM and never lets
network I/O block the renderer. Replacing the ASIO device side with an RTP
sender therefore touches no DSP, no pool and no renderer code.

## 2. Data flow

```
Rust renderer (writer thread)
  │ in-place DSP via processPool()                     output_stream.zig:166-183
  ▼
Rust pool block (480 frames x N ch f32, stable token)
  │ publishPool() -> 32-slot descriptor ring            output_stream.zig:28,185-204
  ▼
NSP owner thread (1 ms service loop; 4 leases/pass)     asio_control.zig:169-174 (ASIO today)
  │ nsp_aes67_submit(lease.pcm, lease.frames)  <-- COPIES into tx ring, then
  │                                              releaseLease() immediately
  ▼
AES67 tx ring (bounded, f32 interleaved)               aes67_tx.c
  │ paced thread, absolute QPC timeline + catch-up burst
  ▼
RTP/AVP packet: 12 B header + L24 BE interleaved       aes67_tx.c build_packet()
  │ sendto() unicast or multicast (TTL/LOOP/IF)
  ▼
UDP -> receiver (PTP-locked network clock)
```

The zero-copy boundary is the same as for ASIO: the lease is a pointer hand-off,
but the sender copies into its own ring before returning the lease, so the
renderer never waits on the network (`docs/core/output-pool-processing-20261022.md:15-17`
already documents that ASIO also copies internally).

## 3. Wire format

| Field | Value |
|---|---|
| RTP version / padding / extension / CC / marker | 2 / 0 / 0 / 0 / 0 |
| payload type | 96 (dynamic) |
| encoding | L24, big-endian, interleaved, 3 bytes/sample |
| sample rate | 48000 Hz only |
| channels | 1..16 (all seven NSP layouts fit; 9.1.6 = 16) |
| packet size | 12 + frames x channels x 3 bytes |
| frames per packet | 48/96/192/480 => 1/2/4/10 ms (`a=ptime`) |
| timestamp | advances by exactly `frames_per_packet` per packet |
| SSRC | fixed per session, default `0x4E535036` |

Multicast defaults: `IP_MULTICAST_TTL` = 32, `IP_MULTICAST_LOOP` = 1, optional
`IP_MULTICAST_IF`. Unicast (e.g. `127.0.0.1` for tests) is plain UDP.

## 4. SDP

Generated by `aes67_sdp.c`. Example for the default 7.1.4 layout
(`contracts/output-layouts.json:9`):

```text
v=0
o=- 1314082870 1314082870 IN IP4 0.0.0.0
s=NativeSpatialPipe AES67 output
c=IN IP4 239.69.1.1/32
t=0 0
m=audio 5004 RTP/AVP 96
a=rtpmap:96 L24/48000/12
a=ptime:1
a=sendonly
a=ts-refclk:ptp=IEEE1588-2008:00-11-22-FF-FE-33-44-55:0
a=mediaclk:direct=0
a=fmtp:96 channel-order=SMPTE2110.(71,4)
a=comment:layout=7.1.4
a=comment:channel-labels=L,R,C,LFE,Ls,Rs,Lrs,Rrs,Ltf,Rtf,Ltr,Rtr
```

* `c=` carries `/<ttl>` **only for multicast**; unicast uses the bare address.
* `a=ts-refclk`: with `--gmid` the SDP declares
  `ptp=IEEE1588-2008:<gmid>:<domain>`; without it a `localmac=02-4E-53-50-00-01`
  placeholder is written and documented as **non-PTP** fallback.
* `a=mediaclk:direct=0` declares that the RTP clock is directly the sample clock.
* `channel-order` and `channel-labels` are **informative**: AES67 does not
  normatively define a channel-order token. The `SMPTE2110.(71,4)` style tokens
  are a pragmatic mapping (grouped 7.1 + quad) generated by
  `tools/aes67-output/gen-layouts.py`; the authoritative label order always
  comes from `contracts/output-layouts.json`.

## 5. PTP dependency (explicit)

AES67 assumes a common PTP (IEEE 1588-2008) time base. **This implementation
does not implement a PTP slave**: it timestamps packets from the host clock at
48 kHz and advertises `ts-refclk` in SDP. Practical options:

1. Real deployment: a PTP slave on the same host (Linux `ptp4l`/`phc2sys`, or a
   NIC with hardware timestamping) disciplines the system/PHC clock; the sender
   inherits it. Windows has no built-in PTP slave; a third-party service or a
   hardware clock is required.
2. Lab/testing: use `a=ts-refclk:localmac=...` (this SDP default) and accept an
   unlocked clock; only RTP timeline continuity is guaranteed, not sample
   accuracy against other endpoints.
3. Windows-side timestamping is `GetTickCount64/QPC` based; it is not
   PTP-disciplined and no `SO_TIMESTAMPING` equivalent is used.

The SDP also does not perform offer/answer negotiation, RTCP, or SAP
announcement: the receiver must be configured with the SDP file.

## 6. Latency and buffering

| Component | Value | Notes |
|---|---|---|
| ptime | 1/2/4/10 ms | 48/96/192/480 frames |
| sender ring | library default 8 packets; CLI 64 | bounded; overflow drops oldest frames and counts |
| CLI prebuffer | 12 packets | test harness only; avoids start-up starvation |
| catch-up burst | <=64 packet periods | keeps average rate correct under OS wake-up jitter |
| NSP integration prebuffer | `network.prebufferFrames` default 480 frames | reuse the existing `Stream` waiting/playing states |

The network path adds no resampler: NSP's source domain is already 48 kHz
(`tools/zig-scheduler/output_processing.zig:20-21`), so the AES67 sink is
sample-accurate as long as the network clock is locked. This is the key
difference from ASIO, where the ASIO module must servo the device clock and
resample (`clock_sync.h`, `sinc_resampler.h`).

## 7. Relationship to ASIO

* **Mutually exclusive output backends**: one session drives either the ASIO
  device or the network sink, never both (one `outputBackend` in playback.json).
* Shared: Rust pool, Zig common DSP (master/trim/delay/limiter), layout presets,
  channel order/routing (`playback-json-configuration-20261022.md:65-79`).
* Different: ASIO owns a physical clock and does clock-servo + SRC; AES67 trusts
  the network/PTP clock and does none. ASIO has `hold`/silence semantics for
  absent input; AES67 sends silence packets and counts them.

## 8. Not implemented

* ST 2022-7 seamless redundancy (dual links / duplicate streams).
* RTCP (SR/RR, receiver reports), SDP offer/answer, SAP.
* PTP slave / hardware timestamping.
* 44.1/96 kHz, non-L24 encodings, AES67 discovery.
* DSCP/QoS marking, IGMP management, multi-stream fan-out.
* Normative ST 2110-30 channel-order conformance (informative only here).

`239.69.1.1` PASS. Measured (2 s, 12 ch, 48 frames/packet): 2010 packets,
999.98 pkt/s arrival rate, 0 lost / 0 out-of-order, SSRC stable
(`0x4E535036`), timestamp step exactly 48, payload 1728 B/packet, L24 tone
1000 Hz with per-channel amplitude ramp, SDP all required lines present,
nominal payload 13824 kbps (13920 kbps on wire including headers). `Test-Aes67.py` writes the measured result to `tools/aes67-output/out/results.json` at run time (the directory is not committed).
