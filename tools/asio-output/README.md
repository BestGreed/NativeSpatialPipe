## Minimum call contract

1. The same working thread creates and initializes the configuration, `struct_size=sizeof(nsp_asio_config)`, `abi_version=1`, and the initial value of the output handle is NULL. The driver ID is UTF-8 `asio:`. Source/physical channels all start at 0, source PCM fixed 48 kHz, interleaved f32, up to 32 channels. Configuration array/string copied before open returns.
2. `open` creates the driver and existing queue, and initializes the STA COM when the current thread holds it; when the calling thread is already an MTA, it will fail explicitly and the thread will not be migrated implicitly. The actual machine of N08 found that DVS is registered as Apartment, and MTA activation will return `E_NOINTERFACE` because the private interface cannot be marshaled across apartments, so the thread model of N04 is corrected. The module does not create a working thread, and all handle calls are executed serially by the creation thread and cannot be placed in the audio callback; the existing dedicated control thread processes driver messages through `service`.
3. `start` allows the silent callback to be initiated first; the caller prepares the data according to `get_stats.minimum_prime_frames` and its own bounded buffering strategy, and then `prime` again. Prime pre-source time does not advance. The interface only provides the required number of frames and does not determine the pre-buffering time limit or scheduling for the upper layer.
4. `submit` replicates PCM synchronously; `first_frame` increases continuously from 0, and the caller guarantees at least `frames*source_channels` readable samples. Unaccepted parameters/samples do not count towards submitted frames. Existing queue capacity is retained, overflow is a fault, and old queues are not actively discarded; there is no new buffering optimization.
5. `service` uses zero event wait timeout and continues to use existing driver message processing, filling and post-consumer cleanup; driver calls/Windows message distribution may still block, and does not promise bounded call duration or real-time safety. Execution is paced by a dedicated worker thread, and no coordination loops or audio callbacks can be placed. Data exception returns INVALID, running/driver exception returns DEVICE_ERROR and locks the fault; only observation and closure are allowed after the fault.
6. When explicitly ending the NSP session, first `finish_input`, continue the service to `get_stats.drained`, and then `stop`. The application not sending the stream temporarily does not mean that the input is completed, and this group of endings is not called. Separate normal emptying from early stopping in case of failure. stop inherits the existing bounded wait downstream and may block; it does not mean that all source PCMs that have been submitted but not yet rendered must have been drained.
7. The device that has been started must be stopped successfully before it can be closed; when it fails, the handle is retained and no false reports are released. close successfully clears the caller's handle to NULL. Empty handle close is idempotent; stopped handle cannot be restarted and must be reopened. Closed or fake handles may not be used.

The interface does not expose C++ containers, allocators, or exceptions across boundaries; return codes are in the header file. `last_error` is the immediate error text of the calling thread. It will be overwritten by the next normal API call and the caller will copy it to its own buffer; memory will not be released across modules. get_stats is still available for error/stop status, but is not a failover entry.

New C entry disables automatic reset and restart: requests such as driver reset/sampling rate change return a fault in the service and are stopped by the host and restarted by the user. Old C++ construct paths retain the original reset behavior for compatibility regression; do not treat the old behavior as an NSP device policy. N06 The production PCM hard truncation and floating point device format hard truncation of the new C entry have been cancelled; the integer device format still performs necessary range saturation. The new entry does not export device volume/trim/delay, the value remains neutral, and the public processor is executed after the renderer and before the device is submitted. The old entry retains calibration and clamp-compatible behavior.

There is currently no device enumeration/control panel or device C API that duplicates public tuning. Software PCM/common processing/owner wiring and bounded rebuffering see N07 delivery (development reference is not provided with the open source code): `nsp_asio_hold` keeps the driver open and pauses source consumption, and fills the ring before resuming; missing samples at the production entry no longer implicitly skip source frames. Statistics are host observations, not DAC clock/acoustic delay calibration.

This machine has confirmed wiring: `L C R Rs Ls Rrs Lrs LFE Ltr Ltf Rtf Rtr`. The official host must add `--asio-channel-order dvs-speakers`; the general default `olr` remains unchanged. The network probe uses this routing by default, with the explicit parameter `--output-order dvs-speakers`. The analysis first identifies which device output each OLR channel actually falls on, and then compares the send/return to avoid speaker semantic errors despite only matching numbers.

The independent probe will enable ROAR to render MMCSS, register on the supply thread, and check the MMCSS registration/priority/deactivation of the real-time sink writer. `renderer-summary.json` saves the actual thread results; the network test build also observes the ASIO owner request results. The driver's own callback only records the thread ID and Win32 priority, which cannot be inferred as MMCSS identity certificate.
